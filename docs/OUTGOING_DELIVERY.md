# Исходящая доставка VK и MAX

Подготовлены отдельные формирователи запросов к официальным API. Они получают единый
ответ ядра и преобразуют его в запрос конкретного канала.

## VK

- метод: `POST https://api.vk.com/method/messages.send`;
- передаются получатель, текст, `random_id` и версия API;
- действия кнопок передаются в payload клавиатуры;
- токен не попадает в исключения и технические сообщения.

## MAX

- метод: `POST https://platform-api2.max.ru/messages`;
- ID пользователя передаётся параметром `user_id`;
- токен передаётся только заголовком `Authorization`;
- кнопки передаются вложением `inline_keyboard` с типом `callback`;
- необходимо соблюдать ограничение не более двух сообщений в секунду одному получателю.

Официальные источники:

- https://dev.max.ru/docs-api/methods/POST/messages
- https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard

## Текущее ограничение

Реальный сетевой транспорт намеренно отсутствует. `MemoryHttpTransport` сохраняет
подготовленные запросы только в оперативной памяти теста. Рабочие токены не нужны.
Подключение реального HTTPS-транспорта и серверной очереди выполняется только после
получения официальных доступов и повторной проверки документации платформ.

## Фоновый исполнитель

Webhook может передать единый ответ ограниченному фоновому исполнителю. Входящий HTTP
запрос не ждёт формирования внешнего API-запроса. Исполнитель:

- имеет настраиваемую ёмкость от 1 до 10 000 ответов;
- считает принятые, обработанные, ошибочные и отклонённые ответы;
- продолжает работу после ошибки отдельной доставки;
- не сохраняет текст сообщения или токен в описании ошибки;
- корректно прекращает приём новых ответов при остановке.

При использовании временного фонового исполнителя переполненный ответ помещается во
внутренний резерв Webhook. Этот режим нужен только для локальной демонстрации; штатный
сервер использует постоянную очередь ниже.

## Постоянная очередь

Для штатного серверного Webhook используется таблица `outgoing_reply_queue` в отдельной
защищённой базе подписчиков. До подтверждения входящего события в ней сохраняется
зашифрованный единый ответ, включая ID получателя, текст, карточки и кнопки.

- ключ события хранится только как HMAC-хеш;
- повторное событие не создаёт второй ответ;
- отправленный ответ повторно не выбирается;
- временная ошибка повторяется с увеличивающимся интервалом;
- после трёх неудачных попыток автоматические повторы прекращаются;
- незавершённая обработка возвращается в очередь после пятиминутной аренды;
- в причине ошибки хранится только тип исключения.

Очередь входит в существующую резервную копию базы подписчиков. Реальная доставка
остаётся выключенной; тестовый исполнитель подтверждает восстановление после повторного
открытия базы.
