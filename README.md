# Чат бот Челябинского театра драмы

Автономный чат бот без внешних языковых моделей. Источник сведений о спектаклях,
афише и артистах — официальный сайт https://www.cheldrama.ru/.

## Текущий этап

Создано ядро распознавания основных запросов и начальная схема базы данных.
Подключения сайта, VK и MAX будут отдельными адаптерами и не изменят логику ядра.

## Запуск тестов

```bash
python -m unittest discover -s tests -v
```

## Обновление локальной базы

Полное безопасное обновление одной командой:

```bash
python scripts/sync_all.py
```

Одновременный повторный запуск блокируется. При ошибке отметка об успешном
обновлении незавершённой части базы не создаётся.

Тестовый контур круглосуточно работает на Linux-сервере в Yandex Cloud. Приложение,
автоматическое обновление и внешнее резервное копирование управляются systemd.
Публичная демонстрация защищена HTTPS и доступна по адресу
`https://vash-kapeldiner.ru`.
Подробности находятся в `docs/SERVER_DEPLOYMENT.md`.

Единая проверка технической готовности:

```bash
python scripts/check_readiness.py
```

Отдельные команды для диагностики:

```bash
python scripts/sync_affiche.py
```

База создаётся в `data/theatre.sqlite3`. Повторный запуск не создаёт дубли.

Полный действующий репертуар загружается отдельно:

```bash
python scripts/sync_repertoire.py
python scripts/sync_play_details.py
```

Афиша отвечает за даты показов, а репертуар — за полный список действующих постановок.

## Локальный диалог

После обновления базы:

```bash
python scripts/chat_local.py
```

Поддерживаются ближайшие спектакли, запросы на сегодня, завтра, конкретную дату
и ближайшие выходные. После загрузки подробностей поддерживаются запросы по названию,
аннотация, режиссёр, состав, жанр, дни недели и новогодняя кампания.

Последние непонятые запросы можно посмотреть командой:

```bash
python scripts/show_unrecognized.py
```

Действующие шаблоны ответов:

```bash
python scripts/show_templates.py
```

Состояние обновления базы:

```bash
python scripts/show_data_status.py
```

Афиша считается устаревшей через 36 часов, репертуар и подробные сведения —
через 7 дней после последнего успешного обновления.

## Локальный виджет сайта

```bash
python scripts/run_web.py
```

Затем открыть `http://127.0.0.1:8080`. Сервер доступен только на этом компьютере.

Технические ошибки записываются в `data/technical.log`. Журнал автоматически
ограничивается по размеру и не содержит тексты сообщений, IP-адреса или данные сессии.

## Подписки

Подписки предусмотрены только в будущих официальных ботах VK и MAX. Сайт предлагает
перейти в один из этих каналов и не собирает данные подписчиков. Подписка на спектакль
включает уведомления о переносе/отмене и напоминание за сутки. Данные и согласия
хранятся в отдельной защищённой базе. Администратору доступны общая статистика и
защищённые персональные карточки с именем, ID, согласиями и предпочтениями; просмотры
таких карточек журналируются.
Требования описаны в `docs/SUBSCRIPTIONS_AND_PRIVACY.md`.

Подготовлена логика рекламных кампаний: выбор аудитории по предпочтениям и каналам,
проверка рекламного согласия, предварительный просмотр, подтверждение и планирование.
Подробности находятся в `docs/CAMPAIGNS.md`.

Демонстрационная проверка подписок и рассылок без VK/MAX:

```bash
python scripts/demo_subscriptions.py
```

Используются только вымышленные пользователи и временная база, которая удаляется
после завершения. Сценарий описан в `docs/DEMO_TESTING.md`.

Локальная демонстрационная административная панель:

```bash
python scripts/run_admin_demo.py
```

Адрес и случайный пароль выводятся в терминале. Панель работает только на
`127.0.0.1`. В ней доступны просмотр аудитории, подтверждение и планирование кампании.
Панель не отправляет сообщения и удаляет временные данные после остановки.
В панели также показывается очередь сервисных уведомлений и доступна безопасная
тестовая доставка во внутренний имитатор канала.

Демонстрация будущего диалога подписки в VK/MAX:

```bash
python scripts/demo_subscription_flow.py
```

Демонстрация очереди напоминаний и изменений афиши:

```bash
python scripts/demo_notifications.py
```

Сквозная демонстрация тестовых событий VK и сценария подписки:

```bash
python scripts/demo_channel_events.py
```

Подготовлены серверные адреса `POST /webhooks/vk` и `POST /webhooks/max`.
Без явно настроенного защищённого Webhook-контура они возвращают `404` и не принимают
события. Реальные сообщения во внешние API пока не отправляются.

Локальная сквозная HTTP-проверка с временными базами и вымышленными секретами:

```bash
python scripts/demo_webhook_http.py
```

Рабочий сервер включает VK и MAX независимо друг от друга только при наличии полного
набора настроек выбранного канала. Секреты можно передать файлами защищённого
серверного хранилища; неполная конфигурация останавливает запуск.

Проверка формирования исходящих запросов VK/MAX без внешней сети:

```bash
python scripts/demo_outgoing_delivery.py
```

Тестовый транспорт показывает адрес и структуру запроса, не раскрывает токены и ничего
не отправляет. Устройство исходящей доставки описано в `docs/OUTGOING_DELIVERY.md`.

Сквозная проверка Webhook и фоновой очереди ответов:

```bash
python scripts/demo_background_delivery.py
```

Очередь ограничена по размеру, работает вне потока входящего HTTP-запроса и передаёт
ответ тестовому транспорту. При переполнении Webhook сохраняет ответ во внутреннем
резерве. Этот резерв пока находится только в оперативной памяти.

Проверка постоянной зашифрованной очереди и восстановления после перезапуска:

```bash
python scripts/demo_persistent_replies.py
```

Штатный серверный Webhook сохраняет подготовленный ответ в базе подписчиков до ответа
платформе. ID получателя, текст, карточки и кнопки хранятся в зашифрованном виде.
Повтор одного события не создаёт второй ответ.

Демонстрация управляемого серверного цикла постоянной очереди:

```bash
python scripts/demo_persistent_worker.py
```

Агрегированное состояние рабочей очереди без расшифровки сообщений:

```bash
python scripts/show_reply_queue_status.py
```

Сквозная проверка сервисного напоминания через общую защищённую очередь:

```bash
python scripts/demo_service_delivery.py
```

Перед фактической доставкой повторно проверяются активная подписка и согласие на
сервисные уведомления. После отписки или отзыва согласия уже подготовленное сообщение
автоматически отменяется.

Сквозная проверка подтверждённой рекламной кампании:

```bash
python scripts/demo_campaign_delivery.py
```

В общую очередь попадают только кампании с подтверждением администратора и наступившим
временем отправки. Рекламное согласие и активный статус проверяются ещё раз перед
доставкой каждого сообщения.

Требования для будущего подключения сайта, VK и MAX находятся в
`docs/INTEGRATION_CHECKLIST.md`.


## Ограничения первой версии

- внешние GPT не используются;
- рабочие Webhook и отправка во внешние API выключены до получения официальных доступов;
- административный кабинет пока существует только в демонстрационном контуре;
- рабочие VK/MAX-подписки включатся после получения официальных доступов и утверждения
  правовых документов театром.
